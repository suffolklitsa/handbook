# Reviewing what an agent wrote

You own every line you submit. Before opening a pull request, go through this list.

## The change

- [ ] Every changed file is one the issue needed. Undo unrelated edits, reformatting and renames.
- [ ] Nothing was deleted that shouldn't have been. Read the red lines as carefully as the green.
- [ ] No secrets, tokens or personal data appear anywhere, including test files.
- [ ] Generated files (marked in each repo's `AGENTS.md`) were regenerated by their script, not edited by hand.

## Facts and law

- [ ] Every rule, requirement, statute, case or office detail has a source you opened yourself.
- [ ] Every citation exists and says what the text claims. Open it. Agents invent plausible ones.
- [ ] Names of buttons, forms, offices and deadlines match the real thing.

## Tests

- [ ] The checks pass when you run them, not just when the agent says so.
- [ ] New behavior has a test that would fail if the behavior broke.
- [ ] The tests check something real. A test that can't fail isn't a test.

## Writing

- [ ] Plain words a first-year would follow.
- [ ] No hype ("seamless," "robust," "powerful") and no padding.

## If you're not sure

Say so in the pull request: "I couldn't confirm X" is useful; a confident wrong answer isn't. Ask in the Build topic on GroupMe.
