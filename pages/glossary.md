# Glossary

| Term | What it means |
|---|---|
| **Repository (repo)** | A project's folder of files plus the full history of every change. Each LITSA project is one repo. |
| **Commit** | A saved snapshot of changes, with a message saying what changed. |
| **Branch** | Your own line of changes, separate from `main` until it's merged. |
| **`main`** | The branch that holds the accepted version. On the site repo, `main` is what's live. |
| **Pull request (PR)** | A request to merge your branch into `main`, where others review it. |
| **Issue** | A task, bug or idea, with a discussion. LITSA issues say what done looks like. |
| **Fork** | Your own copy of someone else's repo, used to propose changes when you aren't a member. |
| **Clone** | A copy of a repo on a computer (yours or a Codespace). |
| **CI (checks)** | Tests GitHub runs on every pull request. A red X means something failed. |
| **Codespace** | A ready-to-use editor and terminal in the browser for a repo. |
| **Terminal** | Where you type commands like `python3 scripts/check_pages.py`. |
| **Markdown** | The plain-text format most LITSA docs are written in (`#` for headings, `-` for lists). |
| **Front matter** | The block between `---` lines at the top of a page, holding its title and other details. |
| **Agent** | An AI tool that can read a repo, change files and run commands. See [what agents are](agents/what-agents-are.md). |
| **`AGENTS.md`** | Each repo's instructions for agents and people: commands and rules. |
| **Token / key** | A secret that grants access to a service. Never put one in a repo. |
| **Generated file** | A file a script writes. Change the script or its input, not the file. |
